# Public Site (Nuxt) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the public Nuxt site (`apps/site`) — the premium-minimalist
one-page landing (hero, objects, about, services teaser, advantages,
reviews, contacts) plus `/services` and `/privacy`, consuming the REST
API built in Plan 1 (Backend). This is Plan 2 of a 4-plan sequence
(Backend → **Site** → Admin → Deploy).

**Architecture:** Nuxt 4 (SSR) app inside the existing pnpm monorepo,
Tailwind CSS v4 via the official Vite plugin, design tokens translated
1:1 from `DESIGN_SYSTEM.md` into a Tailwind v4 `@theme` block. Pages
fetch data from the Plan 1 backend over plain `$fetch` (no GraphQL, no
state-management library — a handful of read-mostly public GET calls
don't need one). Presentational components receive data as props;
page-level components own the data fetching (`useAsyncData`).

**Tech Stack:** Nuxt 4.5.x, Vue 3.5, TypeScript, Tailwind CSS v4
(`@tailwindcss/vite`), `@nuxt/fonts` (Manrope), `@nuxtjs/sitemap`.

**Spec:** [docs/superpowers/specs/2026-09-29-kambyrstroi-platform-design.md](../specs/2026-09-29-kambyrstroi-platform-design.md)
**Depends on:** [docs/superpowers/plans/2026-09-29-backend-foundation.md](2026-09-29-backend-foundation.md) (Plan 1, merged to `master`)

## Global Constraints

- Site structure per spec §8 revision: **one page** (`/`) with all
  sections behind anchor links in the header, plus separate `/services`
  and `/privacy`. No `/about`, `/objects`, `/objects/:slug`, `/reviews`,
  `/contacts` routes in this plan (spec §12 revision).
- Header nav: anchors scroll to sections on `/` (Наши объекты, О
  компании, Отзывы, Контакты); "Услуги" is a real link to `/services`.
- Design tokens (colors, radii, shadows, spacing, typography) come
  verbatim from `DESIGN_SYSTEM.md` §22 ("CSS Variables — Ready to Use")
  and §2–§5 — translate them into a Tailwind v4 `@theme` block, don't
  invent new values.
- Asymmetric hero split **55/45**, `grid-template-columns: 1.30fr 1fr`,
  large `38–40px` radii, monochrome palette only, extremely soft shadows
  — the non-negotiable constraints in `DESIGN_SYSTEM.md` §23 apply.
- API base URL is configurable via `NUXT_PUBLIC_API_BASE` (runtime
  config), defaulting to `http://localhost:3000/api` in dev — matches
  Plan 1's backend default port and `/api` prefix.
- Site dev server runs on **port 3001** — Plan 1's backend `.env.example`
  already whitelists `http://localhost:3001` in `CORS_ORIGINS`.
- **No `packages/shared` TS package** (a deviation from the spec's
  original monorepo sketch in §3, mirroring a similar pragmatic call
  already made in Plan 1): with a single consuming frontend and no
  cross-package build tooling set up, a hand-written local types file
  (`apps/site/app/types/api.ts`) mirroring the Plan 1 DTOs is simpler
  than standing up a shared package for a handful of interfaces. Revisit
  once the admin app (Plan 3) also needs these types.
- **No frontend test runner introduced in this plan** — per spec §10
  ("Frontend: без объёмного покрытия в MVP; визуальная приёмка по
  чек-листу DESIGN_SYSTEM.md §25"). Verification per task is: `nuxi
  typecheck` passes, the dev server renders the feature correctly
  (checked visually, including at mobile width), and no console errors.
  Team/TeamMember data from the backend is **not** surfaced on the site
  in this plan — the current one-page scope (spec §8 revision) has no
  team section; the API already supports it for when it's needed.

- [ ] **Step 2: Fetch composables**

```typescript
// apps/site/app/composables/useApi.ts
import type {
  Advantage,
  CreateLeadPayload,
  CreateReviewPayload,
  ObjectItem,
  Review,
  Service,
  SiteSettings,
} from '~/types/api';

function apiBase(): string {
  return useRuntimeConfig().public.apiBase;
}

export function fetchSettings() {
  return $fetch<SiteSettings>(`${apiBase()}/settings`);
}

export function fetchServices() {
  return $fetch<Service[]>(`${apiBase()}/services`);
}

export function fetchAdvantages() {
  return $fetch<Advantage[]>(`${apiBase()}/advantages`);
}

export function fetchObjects() {
  return $fetch<ObjectItem[]>(`${apiBase()}/objects`);
}

export function fetchObject(slug: string) {
  return $fetch<ObjectItem>(`${apiBase()}/objects/${slug}`);
}

export function fetchReviews() {
  return $fetch<Review[]>(`${apiBase()}/reviews`);
}

export function submitReview(payload: CreateReviewPayload) {
  return $fetch<Review>(`${apiBase()}/reviews`, { method: 'POST', body: payload });
}

export function submitLead(payload: CreateLeadPayload) {
  return $fetch(`${apiBase()}/leads`, { method: 'POST', body: payload });
}
```

**⚠️ Component auto-import note (discovered during execution):** Nuxt's
default component auto-registration prefixes a component's name with

`<LayoutSiteHeader>`, not `<SiteHeader>`. Every component reference in

set this once in `nuxt.config.ts` (Task 2's file, add it now):

```typescript
// apps/site/nuxt.config.ts — add to the config object
components: [{ path: '~/components', pathPrefix: false }],
```

```typescript
export function useLeadModal() {
  const isOpen = useState<boolean>('lead-modal-open', () => false);
  const open = () => {
    isOpen.value = true;
  };
  const close = () => {
    isOpen.value = false;

  return { isOpen, open, close };
}
```

- [ ] **Step 1: Component**

```vue
<!-- apps/site/app/components/leads/LeadFormModal.vue -->
<script setup lang="ts">
const { isOpen, close } = useLeadModal();

const name = ref('');
const phone = ref('');
const comment = ref('');
const consent = ref(false);
const isSubmitting = ref(false);
const isSubmitted = ref(false);
const errorMessage = ref('');

async function handleSubmit() {
  if (!consent.value) {
    errorMessage.value = 'Нужно согласиться на обработку персональных данных';
    return;
  }
  errorMessage.value = '';
  isSubmitting.value = true;
  try {
    await submitLead({ name: name.value, phone: phone.value, comment: comment.value || undefined });
    isSubmitted.value = true;
  } catch {
    errorMessage.value = 'Не удалось отправить заявку, попробуйте ещё раз';
  } finally {
    isSubmitting.value = false;
  }
}

function handleClose() {
  close();
  isSubmitted.value = false;
  name.value = '';
  phone.value = '';
  comment.value = '';
  consent.value = false;
  errorMessage.value = '';
}
</script>

<template>
  <Teleport to="body">
    <div
      v-if="isOpen"
      class="fixed inset-0 z-50 flex items-center justify-center bg-black/40 p-4"
      @click.self="handleClose"
    >
      <div class="bg-card rounded-panel w-full max-w-md p-8 shadow-floating">
        <div v-if="!isSubmitted">
          <h2 class="text-text text-xl font-medium">Оставить заявку</h2>
          <p class="text-text-secondary mt-1 text-sm">
            Свяжемся с вами в ближайшее время
          </p>

          <form class="mt-6 flex flex-col gap-4" @submit.prevent="handleSubmit">
            <input
              v-model="name"
              required
              type="text"
              placeholder="Имя"
              class="border-border rounded-control border px-4 py-3 text-sm"
            />
            <input
              v-model="phone"
              required
              type="tel"
              placeholder="Телефон"
              class="border-border rounded-control border px-4 py-3 text-sm"
            />
            <textarea
              v-model="comment"
              placeholder="Комментарий (необязательно)"
              rows="3"
              class="border-border rounded-card border px-4 py-3 text-sm"
            />

            <label class="text-text-muted flex items-start gap-2 text-xs">
              <input v-model="consent" type="checkbox" class="mt-0.5" />
              <span>
                Согласен(на) на
                <NuxtLink to="/privacy" class="underline" @click="handleClose">
                  обработку персональных данных
                </NuxtLink>
              </span>
            </label>

            <p v-if="errorMessage" class="text-xs text-red-600">{{ errorMessage }}</p>

            <button
              type="submit"
              :disabled="isSubmitting"
              class="bg-primary text-primary-text rounded-control mt-2 px-6 py-3 text-sm font-medium disabled:opacity-60"
            >
              {{ isSubmitting ? 'Отправляем…' : 'Отправить заявку' }}
            </button>
          </form>
        </div>

        <div v-else class="py-6 text-center">
          <h2 class="text-text text-lg font-medium">Спасибо!</h2>
          <p class="text-text-secondary mt-2 text-sm">Мы скоро с вами свяжемся.</p>
```

**Interfaces:**

- [ ] **Step 1: Multi-stage `Dockerfile`** (same reasoning as Plan 1's
  backend Dockerfile — copy the full `node_modules` from the build
  stage rather than trying a `--prod`-only reinstall, since that already
  proved necessary once in this monorepo; verify Nuxt's actual build
  output path the same way before trusting it, per Plan 1's `dist/src/
  main.js` lesson)

```dockerfile
# apps/site/Dockerfile
FROM node:24-alpine AS build
WORKDIR /app
RUN corepack enable
COPY package.json pnpm-workspace.yaml pnpm-lock.yaml ./
COPY apps/site/package.json apps/site/package.json
RUN pnpm install --frozen-lockfile --filter site...
COPY apps/site apps/site
RUN pnpm --filter site build

FROM node:24-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/apps/site/.output ./.output
EXPOSE 3000
CMD ["node", ".output/server/index.mjs"]
```

**Note:** Nuxt's `nuxi build` produces a self-contained `.output/`
directory (server code + bundled dependencies) — unlike the NestJS
build, there's no need to copy `node_modules` separately here; verify
this assumption by actually running the container (Step 4) before
trusting it.

```yaml
    build:
      context: .
      dockerfile: apps/site/Dockerfile
    restart: unless-stopped
```

```nginx

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

}
```
